## R — The Data Rules & SEC EDGAR Hierarchy

All financial facts are extracted keylessly from the SEC EDGAR API (`https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json`) using a formal user agent header: `User-Agent: Lucas Timm ltimm@purdue.edu`.

### Ingestion Rules

| Category | Ingestion Rule | Operational Implementation in `buffett.py` |
|:---|:---|:---|
| **Filings** | Form `10-K` only | Ignores `10-Q`, `8-K`, and registration statements; filters on `form == "10-K"`. |
| **Flows** | 1-Year period required | Restricts duration between `start` and `end` dates to $330 \le \text{days} \le 400$. |
| **Revisions** | Latest filing date wins | When multiple filings report on the same fiscal year end, the row with the maximum `filed` date supersedes earlier vintages. |
| **Revenue Tag** | Primary: `RevenueFromContractWithCustomerExcludingAssessedTax` | If absent, falls back to `Revenues`. |
| **Net Income Tag** | `NetIncomeLoss` | Primary GAAP tag for consolidated net income. |
| **Operating Cash Flow** | `NetCashProvidedByUsedInOperatingActivities` | Audited cash generated by core operations. |
| **Capital Spending** | Primary: `PaymentsToAcquirePropertyPlantAndEquipment` | If absent, checks `PaymentsToAcquireProductiveAssets`. |
| **Stockholders' Equity** | `StockholdersEquity` | Point-in-time balance sheet equity at fiscal year end. |
| **ROE Formula** | $\text{Net Income} \div \text{Equity}$ | Expressed as percentage to one decimal place. |
| **Owner Earnings** | $\text{OCF} - \text{Capital Expenditures}$ | Buffett's free cash flow metric to equity owners. |
| **Missing Tag Rule** | Mark as `"not found"` | Never interpolate, estimate, or fill from third-party consensus. |
| **Negative Equity Rule**| Mark ROE as `"not known"` | Prevents dividing positive net income by negative book equity from yielding falsely positive ROE. |
| **Missing Input Check** | Check outcome is `"not known"` | If CapEx or Equity is missing, corresponding checks output `"not known"`. |

## Explain the Code (Line by Line)

### Extraction Logic in `buffett.py`

```python
def extract_flow_metric(us_gaap: dict, tag_priority_list: list) -> tuple:
    for tag in tag_priority_list:
        if tag not in us_gaap:
            continue
        units = us_gaap[tag].get("units", {})
        usd_items = units.get("USD", [])
        if not usd_items:
            continue

        entries_by_end = {}
        for item in usd_items:
            if item.get("form") != "10-K":
                continue
            start = item.get("start")
            end = item.get("end")
            val = item.get("val")
            filed = item.get("filed", "")
            if not start or not end or val is None:
                continue

            try:
                duration_days = (datetime.strptime(end, "%Y-%m-%d") - datetime.strptime(start, "%Y-%m-%d")).days
                if not (330 <= duration_days <= 400):
                    continue
            except ValueError:
                continue

            if end not in entries_by_end or filed > entries_by_end[end]["filed"]:
                entries_by_end[end] = {
                    "val": float(val) / 1e6,
                    "filed": filed
                }

        if entries_by_end:
            res = {end: data["val"] for end, data in entries_by_end.items()}
            return res, tag

    return {}, "not found"
```

### Partner Question & Answer
- **Partner Question (Miles Nine):** *Where does "not found" come from in the code, and why doesn't the script fall back to an estimate?*
- **Analyst Explanation from Code:** If none of the tags in `tag_priority_list` exist inside `us_gaap`, or if no entries meet the `form == "10-K"` and $330 \le \text{duration} \le 400$ filters, the loop exhausts all options and hits the terminal return line: `return {}, "not found"`. The script deliberately contains no fallback to regression estimates, peer averages, or outside web data.

## Agent Skills — Learn on Your Own

### 1. What is an Agent Skill?
An agent skill is a version-controlled, modular directory containing instructions (`SKILL.md`), scripts, and procedures that teach an AI agent how to reliably execute a domain-specific workflow.

### 2. How Does It Work — Why Does the AI Read Only Name & Description First?
To conserve context window limits and maintain fast response times, the agent runtime indexes only the `name` and `description` frontmatter across all installed skills. The full operational instructions and bundled code are progressively disclosed and ingested into the model's active memory only when a user prompt matches the description trigger.

### 3. Why Do Numbers Belong in Code, Not in the Model?
Large Language Models are probabilistic pattern matchers, not calculation engines. They are prone to token hallucination, transposition errors, and rounding drift when performing multi-year financial calculations. Placing numeric extraction, accounting checks, and metric computation inside deterministic Python code guarantees mathematical accuracy, while reserving the model for qualitative evaluation.

## Reflect

1. **What the Skill Makes the Same Every Time vs. What It Leaves to the Model:**  
   The skill guarantees that data ingestion, tag hierarchies, duration filters, revision handling, and check thresholds (e.g. 15.0% ROE) execute with identical, deterministic precision on every run. It leaves to the model the synthesis of qualitative franchise characteristics, competitive risk assessment, and drafting natural language investment memos.
2. **Why "Not Found" is Better Than an Estimate:**  
   In quantitative financial modeling, an invented estimate disguises missing fundamental facts as verified accounting reality. Displaying `"not found"` protects institutional decision-makers from trading on false assumptions and correctly surfaces when a company's business model (like commercial banking) requires an alternative evaluation framework.
